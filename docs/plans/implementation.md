### The exact next action

**Both are now built, and so is the pipeline behind them.** The retrospective runs against any
clone; the endpoint binds, authenticates, de-duplicates and answers 202 inside GitHub's ten
seconds; and the work callback in `serve/commands/run_endpoint.py` calls
`serve/review/review_delivery.py`, so a delivery is reviewed rather than dropped.

**Next is the first real installation.** Every piece joins up in process — `ingest/` reads history
and a diff, `rank/` orders the changed files, `allocate/` funds the top of that order, `infer/`
reads only there, `verify/` adjudicates, `render/` writes the comment, `serve/webhook_github.py`
decides which deliveries are ours, and `store/deliveries.py` makes a retry safe — but **no check
run has ever been posted to a real pull request**, and the write path has only been exercised in
rehearsal under `QUANTAMIND_POSTING_ENABLED=0`. An endpoint that works against a fixture and one that
works against GitHub are different claims, and only the first is evidenced.

The binding still needs a deployment, a GitHub App and an install before it delivers a coverage
line to anyone. Distribution remains the weakest point in this company, and the retrospective — one
clone, no access, no install — is the only bottom-up motion. See `docs/product/QUANTAMIND.md`.

**The socket exists and the dependency choice went to stdlib.** `serve/listener.py` serves
`POST /webhook` and `GET /health` on `http.server`, so `pyproject.toml` still declares
`dependencies = []`. What the endpoint needs is one POST route, an HMAC compare and a status code;
a framework would have been the project's first runtime dependency, paid on every install to save
about forty lines. **`http.server` is not a hardened edge** — no TLS, no rate limiting, no
slow-loris defence — so it runs behind a reverse proxy, and nothing in CI can assert that it does.

**The constant-time comparison now has a guard.** `check_constant_time_compare.py` parses the
module and fails unless `hmac.compare_digest` is used and no `==`/`!=` compares a digest. Crude —
it checks the shape of the code, not its behaviour — but a timing test is unreliable in CI and a
flaky security test gets deleted. GitHub's own words: *"Never use a plain `==` operator."*

**Replay protection exists now, and it did not before.** GitHub signs the body and no timestamp, so
a captured delivery stays valid forever; `store/deliveries.py` keys on `X-GitHub-Delivery`.
A redelivery REUSES that GUID, so `begin()`/`complete()` are separate: an unfinished attempt is
retryable, a finished one is not.

The reader stage is otherwise complete. Every layer from git to a rendered comment now exists,
**and the endpoint listens**: `serve/listener.py` serves `POST /webhook`, `webhook_github.py`
decides which deliveries are ours, and `run_endpoint.work()` calls `review_delivery.deliver()`.
**CORRECTED 2026-09-11 — this sentence read "nothing yet listens for a pull request" while the
section above it, 28 lines earlier, said the endpoint reviews.**

**The posting gap is closed.** `post()` has written a real comment, refused a duplicate on the same
head, and posted again when the head moved — by hand, against our own repository, comments deleted
afterwards. `serve/` can call it.

The pipeline now runs end to end through product code alone: `ingest/diff.py` supplies the changed
paths and the bounding commit, so the live tests no longer hand-fetch anything.

**The ranker stage's gates are all four MET.** **2a** (zero ordering mismatches), **2a′**
(3.37% against alphabetical's 6.40% over 1,188 events), **2c**, and now **2b** — the product
reproduces `defect_return_external.json` event for event on all six pinned repositories, 2,400
events, miss **1.21%** against **3.12%**.

**Gate 2b failed on its first honest run and found a live defect in `ingest/commits.py`.** A
pathspec turns on git's history simplification, which drops commits that really did touch the
path; the reader lost 3 to 151 commits per repository, and 23 of 430 for one celery file. The
score IS the touch count, so those were ranking errors. `--full-history` fixes it, and
`test_counts_match_git.py` had been using that flag as its ORACLE all along — the oracle was
right and the reader was wrong, and the test passed anyway because its repositories have flatter
histories than the pinned six.

# The rule that governs every gate here

Each stage has a gate that can **fail**. A gate that cannot fail is decoration.

So each gate below is written with its **known-answer test**: what the check outputs when the thing
it checks is broken. If that answer is "the same thing", the gate is rewritten before the stage
begins.

**And the sabotage must break the whole mechanism, not its entry point.** A previous sabotage
disabled an entry point, left the suite green, and was read as coverage. Another broke a
normaliser in a way that preserved the equality under test.

# Stage — The reader  ·  STARTED

**Goal: read a repository and a pull request into typed values. No ranking, no model.**

### Steps

1. **DONE — PR #46.** `ingest/history.py` — walk history once per repository. **Assert the git exit
   code on every call**; raise a typed error, never return a short list.
   Built with: shallow and blob-filtered clones refused up front; a repository with no commits
   returning `[]`, detected via `rev-parse --verify HEAD` rather than by matching git's wording;
   merge commits excluded so they cannot swamp the counts.
2. **DONE.** `ingest/diff.py` — the pull request's changed paths and the commit that bounds the
   ranking window. **The base, never the head**: ranking against the head would count the pull
   request's own commits as prior history, so a branch would raise its own score. A base absent
   from the clone is refused, not guessed — a ranking against the wrong instant looks identical to
   a correct one. Hunks and line ranges are not built; nothing needs them until `parse/`.
3. `ingest/github_pulls.py` — pull request metadata. **Timeout 30s, declared.**
4. **DONE, both paths verified.** `ingest/publish/github_comments.py` — one comment
   per head SHA. The key is the head SHA rather than the pull request number: a pull request lives
   for weeks and its head moves, so keying on the number would comment once and go silent for every
   later push. **The decision is a pure function** so the half that can double-post is the half
   tested exhaustively. `post()` writes under a real identity so **no test calls it**; it was
   exercised by hand against our own repository — True, then False on the same head, then True on a
   new head — and the comments deleted.
5. `parse/languages.py` — which languages we parse and to what depth. **Public, and printed in the
   coverage line.**
6. `parse/units.py` — map hunks to the functions they touch. Two passes: git's funcname diff
   drivers as the cheap first pass, tree-sitter as the exact one.
7. Everything unparseable emits `Unresolved(site, reason, construct)`. **Never nothing.**

### Output

`uv run quantamind read <repo> <pr>` prints changed units, signatures and the unresolved list as
JSON.

### Tests

- **Unit:** each reader against a repository built for the case — done for `history.py` with ten
  such tests. **No mocked subprocess output**: a mock asserts that our parser parses our own
  fixture string.
- **Property:** `parsed units + unresolved sites == total sites` for every diff. Nothing vanishes.

### Live verification

Against the pinned submodules in `tests/live/fixtures/repos/`, run `read` and diff against a
checked-in golden file **reviewed by a human**.

### Gate

**Conservation holds on every live fixture**, and a file in a language we do not parse appears in
`unresolved` with a reason rather than being absent from both lists.

**Known-answer test, already applied to step 1:** delete the exit-code check *whole* and
`test_a_git_failure_mid_read_raises_instead_of_returning_a_short_list` goes red. Removing only the
`raise` would sabotage the entry point.

**Known-answer test for parsing:** disable the tree-sitter path **and** the funcname path. A
previous sabotage here disabled only the entry point and left the suite green.

### What could silently fail

- **A renamed file reads as new — MEASURED, and deliberately not solved.** `--name-only` reports
  the new path, so history before the rename is invisible and the file lands in the no-history
  class. `git log --follow` is per-path and does not compose with `--name-only`. **The size is now
  known and it is the reason this stays open**: see "The renamed-file blind spot, sized".
- **A blobless clone.** 27 of 35 clones in the research corpus are `blob:none`; a cold read fetches
  trees over the network, and a network failure looks like a small repository. `history.py` refuses
  these outright — `ingest/diff.py` must make the same choice, not a different one.
- **The 1800s history timeout is a guess.** It raises rather than returning what it had, so the
  failure is loud, but the number is unvalidated until a repository approaches it.

# Stage — The store and the ranker  ·  STARTED

**This is the stage that decides whether the research is the product.**

Read `docs/plans/design/storage.md` before step 1 and `docs/plans/delivered/feat/rank-fix-history.md` before
step 3. The schema is versioned and append-only: a column that must exist from the first row cannot
be backfilled.

### Steps

1. **DONE.** `store/schema.py` — the versioned SQLite schema and `SCHEMA_VERSION`. Changing it
   requires a migration and a bump; there is no "delete it and re-index" in production. Built with
   `open_store()` refusing a database written by another version rather than migrating in place,
   and the three un-backfillable columns present from the first row: `shadow_pick`'s ranked list,
   `request.cache_read_tokens`, and `outcome.rule_version` with `fix_subject`.
2. **DONE.** `store/touches.py` — the touch index. Bounded strictly by the parent commit; the
   window is half-open, `[as_of - window, as_of)`, and `as_of` is required with no default because
   a default would silently be the present. Re-indexing replaces rather than appends, since a
   repository ingested twice would double every count evenly — an error that moves no ordering and
   corrupts the percentile.
3. **DONE.** `rank/score.py` — `order()`, `discriminate()`, `top()` and `rendered()`. Pure, no
   I/O. `Touch` moved to `types/history.py` during this step: `store/` sits LEFT of `ingest/`, so a
   value object shared by both belongs to the leftmost layer.
4. **DONE.** `rank/order.py` — the budget of three, the `Allocation` labels and the firing
   percentile. Ranks FILES: `Site(path, line=0)` is what declares that, since function-level
   top-three misses 8.84% against the file's 1.22%. Does not re-order — the sequence comes from
   `score.order()` untouched, because gate 2a compares it element by element.
5. `rank/discriminate.py` — the three-case split from the ranker plan. A `Ranking` that does not
   distinguish *ordered by history* from *no history to order by* claims a capability it did not
   exercise.
6. A `NullRanker` **in the test tree, not in `src/`** — alphabetical, non-informative, run on every
   gate as the control.

### Output

`uv run quantamind rank <repo> <pr>` prints the ranked units with scores and the fire decision.

### Tests

- **Unit:** `rank/score.py` against hand-built indexes — pure function, no repository needed.
- **Property:** the ordering is total and stable; equal scores break by path, never by input order.
- **Control:** every gate below runs the `NullRanker` beside the real one. **A gate the null also
  passes is measuring the corpus, not the ranker.**

### Live verification

Against at least **three pinned submodule repositories**, run the productionised ranker over the
same events as `research/phase0/external/defect_return.py`.

### Gate — three, because they fail for different reasons

| | gate | passes when |
|---|---|---|
| **2a** | **ordering identity** | `rank/`'s ordering matches `defect_return.py`'s **exactly**. Not "similar" — the same list. A reimplementation that reorders anything has changed the policy, and the policy is what has the p-value |
| **2b** | **reproduces the research corpus** — **MET** | the product's (hit, alpha_hit) vector is IDENTICAL, event for event, to `research/phase0/external/defect_return_external.json` on all six pinned repositories: 2,400 events, miss **1.21%** against alphabetical **3.12%**. **This gate was written as "miss inside 0.82–1.81%" and that interval was the wrong one** — it is Wilson on 24/1969, the ORIGINAL EIGHT the ranker was developed against. The fresh six have their own interval, [0.84%, 1.73%] on 29/2400, and pairing one population with the other's interval is the category error the gate itself warned about. Equality is also strictly stronger: once the events match, the miss rate is 1.21% by construction, where an interval admitting 0.84–1.73% would pass a product that had drifted. Run with `just gate-2b` after `just fixtures`

| **2a′** | **beats the control** — **MET** | replayed over **1,188 admissible events** from four repositories, ranker miss **3.37%** against alphabetical **6.40%**. A gate the null also passes is measuring the corpus |
| **2c** | **all three cases reachable** — **MET** | all three render materially different lines against a reviewed golden file (`tests/unit/golden/coverage_lines.md`). Live, `ordered` and `no_history` both occur and their lines differ; **`flat_nonzero` did not occur in 40 pull requests across five repositories** and is covered by the fixture alone, which the live run prints rather than passing over |

**2a does not wait on the others and it is the one that can end the project. It PASSES**: zero
ordering mismatches over 1,188 replayed events, with the event definition — 2–12 files, a
fix-subject within ninety days matched CASE-INSENSITIVELY, the flat-score skip, the 400-event cap
— copied from `defect_return.py` rather than chosen. The case rule was wrong until gate 2b was
built: `commit_stream.py` lowercases the subject before the research ever matches it, and the
replay carried a comment asserting the opposite where nothing could check it.

**Why the miss rate varies so much between repositories, mechanically.** `httpx` events touch 5.3
files on average against `pip-tools`' 3.4, and top three covers 57% of a 5.3-file change against
88% of a 3.4-file one. **80% of httpx's misses are files that HAD prior history and lost anyway**,
so this is not the no-history class — it is the budget meeting larger changes. It is the large-PR
triage result arriving from a third direction.

**Known-answer test:** break `rank/score.py` to return a constant. Gates 2a and 2b must both fail.
Breaking only `rank/order.py`'s tie-break would sabotage the entry point — the mechanism is the
count.

**Second known-answer test:** feed the ranker a corpus where every file ties at zero. It must
produce the no-history label, not an arbitrary order presented as a ranking.

### What could silently fail

- **Ordering identity can pass on a corpus too small to discriminate.** Three repositories that
  happen to contain few ≥4-file changes would match trivially. **Mitigation:** 2c requires all
  three cases present, and the count of ≥4-file changes is printed beside the result.
- **The 365-day window was measured on repositories with more than a year of history.** A younger
  repository is the no-history case, not a special one — but nothing yet asserts that.
- **`rank/` importing `ingest/` would make the pure function impure** and the layer guard is what
  stops it. If the guard is walking the wrong directory (see “Stage — The skeleton”), nothing stops it.

# Stage — Serve  ·  STARTED

### Steps

1. **DONE (decisions only).** `serve/webhook_github.py` — `verify()` authenticates a delivery,
   `interpret()` decides whether it is ours to act on. **An absent secret RAISES rather than
   skipping verification**, which is how an endpoint becomes an open command channel while every
   test that supplies a secret passes. **No HTTP binding yet**: `pyproject.toml` declares
   `dependencies = []`, so the socket layer is a separate decision about whether to take a
   framework or use stdlib.
2. **DONE.** `serve/health.py` — it OPENS the store rather than pinging it, because version
   mismatch and schema drift are what a deploy produces and both are invisible to a file check.
   It never raises: an orchestrator needs a verdict, not a stack trace.
3. **DONE.** `serve/listener.py` and `serve/commands/run_endpoint.py` — the socket, on stdlib. **Verify
   before parse**: the body is read by `Content-Length` and handed to `verify()` as raw bytes, and
   `Content-Length` is bounded at GitHub's 25 MB because it is attacker-controlled. **Answer, then
   work**: GitHub wants a 2XX in ten seconds and a real run will not finish in ten, which is what
   the separate `begin()`/`complete()` were built for.
4. **NOT BUILT.** The work callback is wired to a logger. `review` joins `ingest` → `rank` →
   `render` behind it; until then the endpoint authenticates and acknowledges and reviews nothing.

fail." Both hold, over a real socket rather than a stub: `tests/unit/layers/serve/test_listener.py`
binds the real server and posts genuine and forged deliveries at it.

**Known-answer tests, and each one caught its sabotage.** Point the health check at a dead store —
if it still reports healthy it is checking that the process is running, which the process already
told us. Skip signature verification, ignore the replay check, drop the `Content-Length` ceiling,
let `build()` accept a whitespace secret: four sabotages, four failures.

**The one that did not fail is the one worth recording.** Removing `flush=True` from the startup

reads as "stuck", not "broken". The read is bounded now. The underlying defect was that

# Held in reserve — Allocate, infer, verify  ·  NOT SCHEDULED

**`infer/` and `verify/` are not built and not planned.** This section exists so the conditions to
open them are fixed in advance rather than argued for later.

**The bar:** published findings under **50% wrong on unique findings**, held **twice**, at least
once with a rater **who did not design the experiment**. It has never held once. Nine designs; four
now owe an independent grader.

**What was tried and moved the headline nothing:** anchor repair, structured context, a rejection
filter, enclosing-function expansion, the repository's conventions file. Expansion *did* remove the
class it targeted — wrong-because-it-did-not-follow-shown-code fell **73.3% → 18.8%** — and the
total did not move because **CI-config findings are 66.7% wrong with 23 of 24 undecidable from a
diff**. Multi-review aggregation was retired on measurement: 4 of 5 correct findings came from
exactly one arm, so keeping what recurs lands *below* a single run.

**The binding number is not the wrong-rate.** It is **0.013–0.037 correct findings per pull
request** — one useful comment per 27 to 77. A filter cannot raise it; removing wrong findings
cannot manufacture correct ones.

**`verify` ships in the same change as `infer`, never after it.** A reviewer publishing unchecked
model claims for even one release is the failure this product exists to prevent.

# The reviewer half — what it is, and the one constraint that is not negotiable

**`allocate/`, `infer/` and `verify/` are scheduled, not reserved.** They were closed on evidence
and re-opened by a product decision on 2026-08-20: without a reviewer there is no product anyone
buys, which is what the competitive work against Qodo, Greptile and CodeRabbit and fourteen tested
designs were for — deciding *how* to use a model, not whether to.

**The evidence that closed them has not been withdrawn and is now the specification.**

## What the measurements still say

**Raw findings are 66.7–82.1% wrong** across four blind rater pools and two corpora, at
**0.013–0.037 correct findings per pull request**. Design thirteen, recomputed from its own
artefacts: **W/n 52.3%, C/n 8.1%** on 86 real findings, with the rater catching 10 of 10 planted
sabotage. **Nine designs of prompt engineering moved that nothing** — anchor repair, structured
context, a rejection filter, hunk expansion and a conventions file.

**So the fix is not a better prompt, and it is not a better reviewer. It is the judge.**

## `verify/` — ONE judge, isolated, and a different family from the reviewer

**This is the reliability mechanism and it is the reason the reviewer can ship at all.** Nothing
`infer/` produces reaches a pull request until `verify/` clears it.

**The isolation is already enforced in code**: `AGENTS.md` rule 7 forbids `verify/` importing
`infer/`, so the layer adjudicating the model's claims cannot start trusting them.

**The DIFFERENT-FAMILY requirement is measured, not assumed, and it was measured here.** On
2026-08-20 a judge sharing the subject's model family graded a pool a careful rater had already
graded. It agreed on **34.9%** of 86 findings — and it did not fail randomly. It **ratified the
reviewer's own hallucinations**: it accepted invented claims about which tag a pinned SHA carries,
and it repeated the reviewer's belief that 2026 lay in the future while running in 2026. **A judge
sharing the subject's blind spots certifies them.**

**And the sabotage control did not catch that.** 12 of 12 planted findings caught while the judge
was wrong on a third of the real ones. Sabotage items are grossly wrong; the failure that dominates
this corpus is a confident, well-formed, false claim about an external fact. **The control measures
a proxy, reads 100%, and the quantity it stands for is failing** — rule 14's defect, found inside
the project's own adjudication protocol. A future sabotage pool needs subtly wrong items, not only
grossly wrong ones.

## `allocate/` — the budget, and why it comes first

`product-skeleton.md` defines it as "budget decisions derived from the ranking", with `budget.py`
and `tiers.py`, carrying a ceiling that is "enforced, not a default that drifts". **Allocation
exists to decide where INFERENCE goes**, so it is built before `infer/`, not after: it is what
stops the reviewer reading a whole diff and what bounds the bill. The `Allocation` labels
`rank/order.py` already emits are its input.

## What is still true and must not be re-litigated

**Not a better prompt.** Five mechanisms tried, headline moved for none.

**Not aggregation.** Retired on measurement: 4 of 5 correct findings came from exactly one arm, and
wrong findings recur more often (37%) than correct ones (20%).

**Not a same-family judge**, and not a second pass by the reviewer in its own context. That is the
one thing this document measured directly, and it is the constraint the product sells.

# The renamed-file blind spot, sized

**The plan called this unresolved for months and never put a number on it.** It has one now,
measured on the pinned corpus through the product's own path.

## The mechanism is real and it separates the outcomes

| outcome | n | with a rename-blinded target |
|---|---|---|
| **MISS** | 29 | **4 — 13.8%**, Wilson [5.5%, 30.6%] |
| hit | 2,371 | 24 — 1.0%, Wilson [0.7%, 1.5%] |

**13.6× enrichment, Fisher exact two-sided p = 2.9 × 10⁻⁴**, intervals disjoint. `AGENTS.md`
requires a suspected cause be cross-tabulated against the outcome because **a cause that does not
separate outcomes is a story** — this one separates.

A *rename-blinded target* is a file a later fix returned to, which scored zero prior touches at
`as_of`, and whose path was created by a rename at or before that event. The ranker had seen the
file; it could not recognise it.

## And the size is the other half of the finding

**Solving it entirely moves the headline from 1.21% to 1.04% — 0.17 points, on four events.**

It is also concentrated rather than general: scikit-learn 3 of 12 misses, scrapy 1 of 9, and
**zero in the other four repositories**.

**The seductive number is the wrong one.** Across the corpus, **16.8% of zero-history file-slots
are rename-blinded** — one in six, and 21–26% in ansible, scikit-learn and scrapy. That sounds
large and is nearly harmless: **most rename-blinded files are never the file a fix returns to.**
The blind spot is common; it bites rarely.

## Why it stays open

The fix is available in one pass — `git log -M --diff-filter=R --name-status` alongside the
existing `--name-only` read — and folding those pairs into the index would let a renamed path
inherit its predecessor's touches.

**That changes the touch counts, and the touch counts are what carry the p-value.** Gate 2b would
stop reproducing `defect_return_external.json` exactly, by design rather than by defect, and the
change would need its own pre-registration against a fresh corpus. **Paying that to recover 0.17
points on n = 4 is the wrong trade**, and this entry exists so the next person does not re-derive
the question before reaching the same answer.

## What would change the answer

**A customer whose repository renames heavily.** scrapy and scikit-learn are that shape, and there
the blind spot is worth more than the pooled figure suggests. The retrospective already computes
everything needed to say so per repository — if a prospect's run shows a high rename-blinded share,
that is the trigger to reopen this, and it is a measurement they would be handing us rather than
one we would have to fund.
